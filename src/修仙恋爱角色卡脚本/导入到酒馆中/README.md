# 这几个 json 是干什么的

它们是这张卡的五个脚本，格式和 `初始模板/脚本/导入到酒馆中/脚本-实时修改.json` 一样，
可以直接在 **酒馆助手 → 脚本库 → 导入** 里逐个导入。

## ⚠️ 先别急着用

**正常情况下你不需要它们。** 角色卡本身就带着这五个脚本（在卡片的
`data.extensions.tavern_helper.scripts` 里），导入卡之后它们会进**「角色脚本库」**——
只是要满足两个条件：

1. 在脚本库里把 **「角色脚本」这一组打开**（分组被禁用时下面的脚本一个都不跑，界面上是半透明而不是划掉）
2. **刷新一次酒馆页面**，再进这张卡

这两步做完脚本就正常了。**这是首选路线，不要绕过它。**

## 什么时候才用这里的 json

只有当你的酒馆助手确实加载不出角色脚本库时（版本太老、分组删不掉、环境问题），
才用这里的 json 作为兜底 —— 它们会进**全局脚本库**。

## ⚠️ 用了之后必须注意

**全局库和角色库会同时跑。** 如果你两边都装了同一份，脚本会**执行两遍**：

- 修为结算两次、跨区赶路天数翻倍
- 开局流程弹两次
- 全屏界面挂载两层

所以：**一旦角色脚本库恢复正常，就把全局库里这几条删掉。**

另外 **`mvu.json` 通常不用导** —— 那是官方脚本（id `22d70d1f-…`），你酒馆里多半已经装了；
同一个 id 会被认成同一个脚本，不会多一份，但也没必要再导一次。

## 这几个文件是怎么来的

从 `../index.yaml` 的 `扩展字段.酒馆助手.脚本库` 生成的，内容和卡里带的那份一致。
改了脚本地址之后要重新生成（不是构建产物，是手工同步的）。
